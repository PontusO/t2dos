# Maths Built-ins and T2DOS BASIC Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Kernel-side maths functions for C (part 1), then `basic`, a QBasic-style interpreter that runs `.bas` files written in `edit` (part 2).

**Architecture:** Part 1 adds 19 syscalls (112 to 130) that call the toolchain C library's single-precision functions, and teaches `cc` that these built-ins take and return `float`. Part 2 is a userland program in `basic/`: at load time it compiles the whole source into an in-memory bytecode for a small stack machine (labels, blocks, variable slots and static types resolved, every load-time error reported then), and at run time a VM loop executes the bytecode. Each bytecode position maps back to a source line for messages. Strings are heap blocks owned by exactly one slot or stack entry and freed when replaced.

**Tech Stack:** T2DOS C subset (built by `compiler/cc`), C++ Arduino sketch (arduino-pico), gcc on the PC (native `-m32` build of the interpreter for fast tests), Python 3 test runners, `tools/board.py`.

**Spec:** `docs/superpowers/specs/2026-11-09-basic-design.md`

## Global Constraints

- Maths syscalls, frozen once committed, in the order `sin 112 cos 113 tan 114 asin 115 acos 116 atan 117 atan2 118 sinh 119 cosh 120 tanh 121 exp 122 log 123 log10 124 pow 125 sqrt 126 fabs 127 floor 128 ceil 129 fmod 130`.
- ABI rule: each new call in `sys.h`, the `cc.c` built-in string, `kernel/kernel.ino`, `host_linux.c`.
- Bootstrap rule: `cc.c` gains built-in names and their float typing, never uses them. Userland and `basic/` use only what `cc` compiles: no `static`, `const`, `do`/`while`, `goto`, struct assignment, user variadic functions, doubles, 64-bit ints.
- Everything except `cc.bin` and sources using the new functions stays byte-identical (`md5sum -c` against a pre-change list); `make check` green; `check_toolchain.py --board` and `--selfhost` pass.
- BASIC uses no kernel or `sys.h` change beyond part 1.
- BASIC number output is formatted by the interpreter's own code (integer digit generation), never by `printf`'s `%f/%e/%g`, so the PC build and the board print identically.
- Free PSRAM after a BASIC program ends equals free PSRAM before it.
- No em dashes anywhere (files, comments, commit messages).
- Board: the port may be held by the owner's `screen` session; never kill it; if `fuser /dev/ttyACM*` shows it busy, stop and ask. Power-cycle only with exactly `uhubctl -l 3-1.4 -p 4 -a cycle -d 3`. Kernel build: `FQBN=rp2040:rp2040:ilabs_cpico_2350:flash=8388608_7340032; arduino-cli compile --fqbn $FQBN --build-property "compiler.cpp.extra_flags=-I$PWD" --output-dir build/kernel kernel`, upload with `arduino-cli upload --fqbn $FQBN -p <port> --input-dir build/kernel`. If the board attached is the Challenger 2350 WiFi/BLE instead, use `rp2040:rp2040:challenger_2350_wifi6_ble5:flash=8388608_7340032` and say so in the report. If no board is attached, board steps are reported as NOT RUN, never as passed.
- qemu is not installed: PC tests of BASIC run a native gcc build of the interpreter (Task 2), and the board run is the authority.

## Review Focus

1. A string reassigned in a long loop (`FOR i = 1 TO 100000: a$ = a$ + "x": IF LEN(a$) > 50 THEN a$ = ""` and `NEXT`): free PSRAM back to the start value afterwards, no slowdown. Pinned in Task 4 (`strloop`, board PSRAM check).
2. `GOTO` out of a `FOR` loop or a `SUB`, then re-entering it many times (old QBasic code does this): no stack growth, no crash. Pinned in Task 3 (`gotoout`) and Task 5 (`gotosub`).
3. Typing keys while a program prints in a loop, then `INPUT`: earlier keys arrive in order, Ctrl-C still breaks. Pinned in Task 6 (`keyqueue`, board case).
4. A program with an error on its last line, or without a final newline, or with CRLF line ends (files made on Windows): line numbers in messages right, no crash. Pinned in Task 2 (`crlf`, `nofinalnl`, `lasterr`).
5. Deep recursion (`FUNCTION fib(n)` to depth 1000, a runaway recursive `SUB`): a clean `Out of stack space` error, not a hang or a corrupted board. Pinned in Task 5 (`deeprec`, `runaway`).
