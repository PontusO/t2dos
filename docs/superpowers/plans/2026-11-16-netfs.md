# Network filesystem (/mnt/fs) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A PC directory served by `tools/fileserver.py` appears on the board (and under qemu) as `/mnt/fs`, and every file syscall works on it.

**Architecture:** `fileserver.py` gets a session mode with byte-range requests. One plain C file, `kernel/netfs.c`, holds the protocol client, the block cache and the save rules; it talks to the network and PSRAM only through a small transport interface. `host_linux.c` includes it with a POSIX transport and routes `/mnt/fs` paths to it; the board kernel uses it through an `fs::FSImpl` wrapper (`kernel/netfs.cpp`) and a WiFiClient transport in `kernel.ino`.

**Tech Stack:** C (kernel core, host_linux), C++ (arduino-pico FS wrapper), T2DOS C subset (userland), Python 3 (server, checks).

**Spec:** `docs/superpowers/specs/2026-11-16-netfs-design.md`

## Global Constraints

- Mount point is exactly `/mnt/fs`; one mount; setting kept in `/etc/mount` (line 1 `host[:port]`, line 2 the remote dir).
- New syscall `SYS_mount = 48`: `int mount(char *host, int port, char *dir)`; host `""` unmounts. All four places: `sys.h`, `cc.c` builtin string, `kernel.ino`, `host_linux.c`; add `mount` to `NEWER_BUILTINS` in `tools/check_ref.py`.
- Session protocol exactly as the spec's Protocol section (numbers first, name last; `READ`/`WRITE` at most 4096 bytes).
- Cache blocks are 4 KB; on the board they come from PSRAM and stop at `TMP_MARGIN` free.
- Connection: opened on first use; 2 s connect timeout, 5 s reply timeout; up to 3 tries per request, 10 ms apart after a close; after 3 failures the mount is **down**: calls fail at once, one reconnect attempt at most every 10 s, or at once on `mount`.
- Saving: `OPEN_WRITE` files are written to `.NAME.t2tmp` in the same remote dir and `RENAME`d over NAME at close; append files `WRITE` their dirty blocks in place. A save is retried as a whole up to 3 times; requests inside a save try are not retried separately. A failed save makes `close()` return -1; SD, flash and `/tmp` closes still return 0.
- No new flush syscall.
- Bootstrap rule: `cc.c`, `as.c`, `ld.c`, `ar.c`, `lib/t2obj.c` stay inside the subset; `check_toolchain.py --selfhost` must stay byte-identical.
- Kernel: never add a switch point inside a WiFi call; never touch PSRAM while flash is written (copy through SRAM, as `k_rename` does).
- Writing style in code comments, docs and commits: no em dashes, plain developer wording.

## Review Focus

1. A save to `/mnt/fs` while PSRAM is nearly full (dirty blocks cannot be evicted): `write()` must return a short count, never corrupt or drop earlier data. Test in Task 3.
2. `cd /mnt/fs` then relative paths, `..` out of `/mnt/fs`, and `/mnt/fs` itself (stat, opendir, chdir of the mount root). Test in Task 2.
3. Opening the same remote file twice (one reader, one writer) in one program: the reader keeps its own blocks; the writer's save replaces the file at close; nothing crashes. Test in Task 3.
4. A process that exits without closing a written file: the kernel's cleanup path closes it, so the save happens (or fails) the same way as an explicit close. Test in Task 3.
5. Names at the limits: a path that resolves to 159 bytes, names with spaces, and a temp name that would exceed the limit (save must fail cleanly with -1, not truncate the name). Test in Task 3.

### Task 2: netfs core, reading side, under host_linux

- Modify: `sys.h`, `compiler/cc.c` (builtin string only), `host_linux.c`, `tools/check_ref.py`, `tools/check_netfs.py`, `Makefile` if userland programs are listed there

**Interfaces:**
- Consumes: Task 1's protocol.
- Produces (`kernel/netfs.h`, plain C, `extern "C"` safe):
  - Transport the user of the core provides:
    `int nt_connect(const char *host, int port, int timeout_ms); int nt_send(int h, const void *b, int n); int nt_recv(int h, void *b, int n, int timeout_ms); void nt_close(int h); unsigned nt_millis(void); void nt_sleep(int ms); void *nt_alloc(int n); void nt_free(void *p);` (`nt_recv` returns >0, or -1 on timeout or close; `nt_alloc` returns 0 when the margin would be crossed).
  - Core: `int nfs_mount(const char *host, int port, const char *dir, int check)` (check=1 does `STAT dir` and needs `OK d`; returns 0/-1; host `""` unmounts and fails with -1 while files are open), `int nfs_mounted(void)`, `int nfs_path(const char *abs)` (1 if a resolved path is `/mnt/fs` or below), `int nfs_stat(const char *abs, int *size, int *isdir)`, `int nfs_open(const char *abs, int mode)` (mode `OPEN_READ`/`OPEN_WRITE`/`OPEN_APPEND`, handle >= 0 or -1), `int nfs_read(int h, void *b, int n)`, `int nfs_write(int h, const void *b, int n)`, `int nfs_seek(int h, int pos)`, `int nfs_tell(int h)`, `int nfs_size(int h)`, `int nfs_isdir(int h)`, `int nfs_close(int h)` (0 or -1), `int nfs_remove(const char *abs)`, `int nfs_mkdir(const char *abs)`, `int nfs_rmdir(const char *abs)`, `int nfs_rename(const char *a, const char *b)`, `int nfs_opendir(const char *abs)`, `int nfs_readdir(int d, char *name, int namesz, int *size, int *isdir)`, `void nfs_closedir(int d)`.
  - The cache policy lives behind `static` functions in `netfs.c` (`blk_get`, `blk_dirty`, `blk_make_room`, `file_save`, `file_drop`) so later policies replace only those.
  - host_linux: file descriptors for `/mnt/fs` files are `NFS_FD = 300` + handle; directory handles 4..7.
