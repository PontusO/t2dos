# rcp and ping Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `rcp [-r] src dst` copies files and directory trees between the board and `fileserver.py`; `ping host [-c count]` checks that a host answers.

**Architecture:** `rcp` is a userland program that walks trees itself, one `GET`/`PUT`/`LS`/`MKDIR` request per connection, using `lib/net.c`. `ping` is a userland program over a new syscall `SYS_ping = 91`, added in the four ABI places.

**Tech Stack:** T2DOS C subset (`compiler/cc`), arduino-pico WiFi/lwIP (kernel), `host_linux.c` under qemu-arm, Python 3 (`fileserver.py`, `check_net.py`).

**Spec:** `docs/superpowers/specs/2026-11-16-rcp-ping-design.md`

## Global Constraints

- No em dashes anywhere (code comments, README, commit messages).
- Userland code stays inside the `cc` subset (see CLAUDE.md); match the style of `userland/get.c`.
- `SYS_ping = 91`, signature `int ping(char *host, char *ip)`: ms on success, -1 timeout, -2 unknown host, -3 network down. `ip` gets the address as text (at least 16 bytes).
- Kernel ping timeout 1 s (`WiFi.ping` takes `WiFi`'s `_timeout`, default 15000; set 1000 around the call and put 15000 back). `WiFi.ping` returns the TTL, not a time: time it with `millis()`.
- `host_linux.c` ping: `getaddrinfo` for the name (-2 on failure), then run `ping -c 1 -W 1 -n <ip>` with `popen` and read `time=`; no `time=` means -1. (ICMP datagram sockets are off on this PC: `ping_group_range` is `1 0`.)
- Protocol addition: `MKDIR name` -> `OK` (also when it already exists) or `ERR text`, through `safe()`.
- Remote argument forms: `:path` (saved server and its remote dir), `host:path`, `host:port:path` (that host, starting at `/`). Exactly one side remote.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` only (no session link).

## Review Focus

- A remote tree with an empty subdirectory: the directory must still be created on the other side (Task 3 test).
- `rcp -r` into an existing directory vs. a new name, both directions: `cp` semantics (Task 3 tests).
- Upload to a remote path whose parent does not exist: `server: ERR ...` and exit 1, no hang (Task 2 test).
- A remote directory given without `-r`: `rcp: NAME: is a directory, use -r`, exit 1 (Task 2 test).
- `ping` of a name that does not resolve: `ping: cannot resolve NAME`, exit 1, no 15 s wait (Task 4 test).

### Task 2: rcp for single files

**Files:**
- Modify: `lib/net.c` (new `net_remote`, `net_mkdir`)
- Create: `userland/rcp.c`
- Modify: `tools/check_net.py` (steps, expected files)

**Interfaces:**
- Consumes: `net_load`, `net_norm`, `net_resolve`, `net_open`, `net_request`, `net_recv_to`, `net_readline` (existing), `MKDIR` (Task 1).
- Produces in `lib/net.c`:
  - `int net_remote(char *arg)`: 0 if `arg` has no `:` (local). Otherwise sets `net_host`/`net_dir` (`:path` uses the saved ones, error `no server: ...` as in `net_pick` if none; `host:path` and `host:port:path` set `net_host` to `host` or `host:port` normalised with `net_norm`, `net_dir` to `/` unless it equals the saved server) and runs `net_resolve(path)` so `net_path` holds the remote path; empty path means the remote directory itself. Returns 1, or -1 on error (message printed).
  - `int net_mkdir(char *path)`: one `MKDIR` request on its own connection to `net_host`; 0 or -1 (prints `server: ERR ...`).
  - `int net_isdir(char *path)`: one `LS path` request; 1 if `OK` (reads and discards the listing), 0 if `ERR`, -1 if no connection.
- Produces in `rcp.c`: `int get_file(char *remote, char *local)`, `int put_file(char *local, char *remote)`, each 0 or -1, printing `NAME: N bytes` per file.
