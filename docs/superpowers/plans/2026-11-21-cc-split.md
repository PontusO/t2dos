# cc.c multi-file split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split `compiler/cc.c` (4,641 lines) into functional logic files that each compile separately and link, with zero behavior change.

**Architecture:** Pure code move following the design in `docs/superpowers/specs/2026-11-21-cc-split-design.md`: a shared `compiler/cc.h` (types, macros, `extern` globals, prototypes — the `basic/basic.h` pattern) plus one `.c` per compiler stage. `make`'s `wildcard` on `compiler/*.c` means adding a file needs no Makefile edit.

**Tech Stack:** T2DOS C subset (the committed cc), gcc host build, python3 checkers, qemu-arm + host_linux, RP2350 board over serial (standing permission this round).

**Spec:** `docs/superpowers/specs/2026-11-21-cc-split-design.md`

## Global Constraints

- Pure code move: no behavior, no codegen change; the only source edits are the moves plus `cc.h`.
- Every split file stays inside the committed cc's compile subset (bootstrap): no `static`, `const`, `do/while`, `goto`, struct assignment; names must stay globally unique (no `static` in the subset).
- `compiler/cc.h` has no include guard (cc's preprocessor is limited); each TU includes it exactly once.
- One commit per moved file; run `make` after every change (it rebuilds the whole toolchain and every `root/bin` binary with the changed cc — that is the per-step integration test).
- `tools/check_ref.py` must stay `different: 0` on its corpus (minus the `compiler/cc.c` entry, dropped in Task 2).
- Keep a running ledger in `docs/NOTES-cc-split.md` (goal / moved so far / next) and update the executing-plans ledger `.superpowers/sdd/2026-11-21-cc-split/progress.md` (`task-start`/`task-done` scripts under `/home/pontus/.agents/skills/executing-plans/scripts/`).
- Board gates run in Task 12 only (`check_make.py --board`, `check_toolchain.py --selfhost`); board rules from AGENTS.md (one program on the port, `Remote` from `check_toolchain`, reboot settle 15-20 s).

**The PC selfhost proxy** (defined here, referenced below): the gcc-built cc compiles `root/bin/cc.bin`; the proxy makes that `cc.bin` compile the split again — byte-identity proves the subset and codegen on the PC, for free, every step. Run from the repo root:

```sh
mkdir -p root/src/compiler root/lib && cp compiler/*.c root/src/compiler/ && cp compiler/cc.h sys.h root/lib/
srcs=""; for f in compiler/*.c; do srcs="$srcs /src/compiler/$(basename $f)"; done
qemu-arm ./host_linux -r root /bin/cc.bin -I /lib -o /tmp/cc2.bin $srcs
cmp root/tmp/cc2.bin root/bin/cc.bin && echo SELFHOST-PC-IDENTICAL
```

## Review Focus

- A prototype in `cc.h` that disagrees with its definition (return type, args) — expect `make` or `check_ref` to fail loudly; pinned by both gates in every move task.
- A global defined twice or zero times — expect `ld` to abort the `make` of `root/bin/cc.bin`; pinned by `make` in every move task.
- Cross-TU init order drift (a second `.t2init`, entry stub change) — expect `cc.bin` to behave as the single-file one; pinned by the PC selfhost proxy per move and `--selfhost` on the board (Task 12).
- A file outside the committed cc's subset — invisible on PC, fatal on the board; pinned by `check_toolchain.py --selfhost` (Task 12) and the PC selfhost proxy (every move).
- Board memory/time regression from multi-source cc builds — pinned by the fresh-boot `check_make.py --board` run (Task 12).
