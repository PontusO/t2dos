# `src/` reorganisation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the eight compiled-source directories into a single `src/` folder with zero content changes and byte-identical outputs, keeping every build, checker, and board flow working.

**Architecture:** A pure path refactor: `git mv` the trees, rewrite repo paths in the PC `Makefile`, `.gitignore` and the Python checkers, and update docs. The board layout (sources under `/src`, includes under `/lib`) is a board-side convention and does NOT change — only the checkers' repo-side mapping to it.

**Tech Stack:** GNU make, gcc, Python 3 checkers, git renames; RP2350 board gates over serial.

**Spec:** `docs/superpowers/specs/2026-11-21-src-move-design.md`

## Global Constraints

- Work on a new branch `src-move` from `main` (HEAD `0490771`, the plan commit).
- Move with `git mv` only; the moved files' contents must not change at all (no comment or whitespace edits). Verification: `git diff --find-renames --shortstat main...HEAD -- 'src/**/*.c' 'src/**/*.h' 'src/**/*.cpp'` shows zero non-rename changes, and pre/post-move `root/bin/*.bin` checksums are equal.
- Directories that MOVE: `compiler/ assembler/ linker/ binutils/ lib/ basic/ userland/ kernel/` → `src/<name>/`. Everything else stays (`tools/ tests/ examples/ docs/ android/ third_party/ root/ build/`), and `sys.h` + `host_linux.c` stay at the repo root.
- Board-side paths never change: `Makefile.board` (except its one comment), the `check_make` plan-board command fixture (`want = [...]` lines), and every `REMOTE`/board literal like `/src/cc.bin`, `/lib/sys.h` stay byte-for-byte as they are.
- `make ref` keeps `git show $$(cat build/ref/COMMIT):compiler/cc.c` — that path addresses a HISTORIC commit's tree and must NOT gain the `src/` prefix.
- Emitted binaries must stay byte-identical (`check_ref` `different: 0`, `check_make --board` 8/8, `--selfhost` IDENTICAL ×6).
- Board runs are pre-approved (standing permission); never kill the user's screen on the serial port.
- Do NOT merge or push — the owner gives that word separately.

## Review Focus

1. **Selfhost fixed point across the move** — the `cc.bin` already on the board's SD image (built from the OLD paths) must rebuild the moved sources byte-identically; the staging mapping must produce exactly the old board paths (`/src/compiler/cc.c`). Pinned by Task 5 `--selfhost` IDENTICAL ×6 and the Task 2 mapping rule.
2. **Board layout freeze** — a changed `Makefile.board` token or fixture command silently changes what the board compiles. Pinned by `check_make --pc` (the fixture compares the command parsed from `Makefile.board`) in Task 2.
3. **Historic blob** — if `make ref`'s `git show` path gains `src/`, the ref cc build breaks and `check_ref` degrades to "different" or error. Pinned by Task 2 Step 4's forced `make ref` rebuild plus `check_ref` green.
4. **`sys.h` resolution from the repo root** — `-I .` (gcc), cc's current-dir resolution, and the `root/lib`/`/lib` staging all assume `sys.h` at the root; moving it or dropping `-I .` breaks every board build. Pinned by full `make` + `check_make --pc` in Tasks 1/2.
5. **No content drift in moved sources** — any accidental edit inside `src/**.c` changes emitted bytes and invalidates the selfhost fixed point's meaning. Pinned by the checksum diff and rename-only `git diff` in Task 1.
