# Wall clock (DS1307 + NTP + timer) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One kernel-owned UTC wall clock — DS1307 over `Wire` at boot, SNTP over WiFi when up, RP2350 timer always — exposed as `SYS_time`, plus a `date` tool.

**Architecture:** A vault-style kernel module (`src/kernel/rtc.cpp/h`) keeps `base_epoch + (millis()-base_ms)/1000` plus a valid flag; every correction (chip seed, NTP) rebases it and mirrors into the core clock via `settimeofday`. The sync state machine runs only from the console-poll hook (the `telnetd_service()` pattern) — never a scheduler hook. Userland reads it through the new `time(int*)` builtin → `SYS_time = 105`.

**Tech Stack:** Arduino C++ (esp_hosted core, `Wire`, `WiFiUDP`), T2DOS C subset for userland/cc, Python 3 checkers, qemu-arm + `host_linux` for PC execution.

**Spec:** `docs/superpowers/specs/2026-11-22-clock-ds1307-design.md`

## Global Constraints

- Branch `clock` from `main` (HEAD at plan time `76cd664`).
- Four-places rule for the new syscall: `sys.h`, the builtin string in `src/compiler/cc.c` `main()`, the switch in `src/kernel/kernel.ino`, the switch in `host_linux.c`. `SYS_time = 105`, exactly, after `SYS_delay_us = 104`.
- `cc.c` change is an append to the builtin string only — the board's committed cc must still parse every toolchain source (bootstrap).
- UTC everywhere; no timezones, no DST, no manual `date` setter.
- The kernel already `Wire.begin()`s in `setup()` (kernel.ino ~1253) for `SYS_i2c_write/read = 101/102` — rtc reuses that running bus; add no `Wire.begin`, touch no existing i2c syscall.
- No new task-switch points: `clock_service()` must contain no `k_yield`/`k_wait`/file/flash calls and no blocking waits — UDP is polled with `parsePacket()` under `millis()` deadlines. It is called ONLY from the console-poll hook.
- Sync runs from the console-poll hook and may stall while a foreground program never touches the console — owner-accepted (spec).
- Board runs are pre-approved, but one program may hold `/dev/ttyACM*` at a time and never kill the user's screen. Board tests and flashing target the **Challenger 2350 WiFi**: `FQBN=rp2040:rp2040:challenger_2350_wifi6_ble5:flash=8388608_7340032,espwifitype=esp_hosted` plus `--library third_party/ESPHost` (AGENTS.md). **No DS1307 is on the bench** — chip-precedence is implemented and code-reviewed, and only its probe-false branch is board-verified.
- `make ref`'s `git show` path stays historic; board-side paths (`/src`, `/lib`) unchanged.
- Do NOT merge or push — the owner gives that word separately.

## Review Focus

1. **Selfhost fixed point** — the appended builtin string changes `cc.bin`; the board's committed cc must still rebuild the new sources byte-identically. Pinned by Task 4 Step 6 `--selfhost`.
2. **Console stall** — a blocking `clock_service()` (busy UDP wait, `delay()` in a Wire retry loop) would stutter the shell/edit keystroke path. Pinned by Task 2 Step 5 inspection + Task 4 `check_sh --board`.
3. **Unsynced semantics** — before the first sync `time()` ticks from 1970 with valid=0 and `date` labels it; under `host_linux` valid is always 1. Pinned by Task 1's `clock.c` and Task 4's boot test.
4. **No task-switch point inside clock code** — any `k_yield`/file call in rtc.cpp breaks the kernel invariant silently. Pinned by Task 2 Step 5 grep.
5. **Retry storm on a WiFi-less board** — bad credentials / no route must not make NTP hammer DNS or the console. Pinned by Task 4 Step 3 boot observation + Task 2's deadline/backoff constants.

### Task 2: Kernel clock — rtc module, service hook, syscall case

**Files:**
- Create: `src/kernel/rtc.h`, `src/kernel/rtc.cpp`
- Modify: `src/kernel/kernel.ino` (include + `setup()` ~1253 + the three console-poll sites ~156/161/162 + the syscall switch near `SYS_delay_us` ~829)

**Interfaces:**
- Consumes: `SYS_time = 105` (Task 1), the running `Wire` bus (`Wire.begin()` already in `setup()`), `WiFiUDP` (`WiFi.h`/`WiFiUdp.h`, `beginPacket(const char*, port)` exists in the esp_hosted core).
- Produces (kernel-internal C++, declared in `rtc.h`): `void rtc_init(void);` (call from `setup()` — probe chip, seed clock), `void clock_service(void);` (call from the console-poll hook — NTP state machine, probe re-try), `unsigned long clock_now(void);` (`base_epoch + (millis()-base_ms)/1000`, always ticking), `int clock_valid(void);` (1 once chip-or-NTP seeded). `kernel.ino`: `case SYS_time: { int *vp = (int *)A(1); if (vp) *vp = clock_valid(); return (int)clock_now(); }`.

- [ ] **Step 1: `rtc.h`** — the four prototypes above, include-guarded, with a header comment: vault pattern, console-poll service, UTC.

- [ ] **Step 2: `rtc.cpp`** — plain C++ (the kernel build is not cc-subset-bound). Behavior, all pinned by the spec:
  - Timekeeper: `static uint32_t base_epoch; static uint32_t base_ms; static int valid;` — `clock_now()` = `base_epoch + (uint32_t)((millis() - base_ms) / 1000)`; a correction sets `base_epoch = t; base_ms = millis(); valid = 1;` and mirrors `settimeofday(&tv, NULL)` (`tv_sec = t`) so LittleFS `getLastWrite()` agrees (round-B bridge). Comment the 49.7-day `millis()` wrap: rebasing on every hourly sync keeps it moot; an unsynced board running 49+ days offline is a dev bench, not a deployment.
  - DS1307 (addr `0x68`): `bcd2bin`/`bin2bcd`; read regs 0..6; probe valid iff bit 7 of reg 0 (CH) clear and decoded epoch in `[1577836800, 4102444800)` (2020..2100); `rtc_write(uint32_t epoch)` writes regs 6..0 then 0 with CH clear. Transactions: one `beginTransmission`/`write`/`endTransmission` or `requestFrom` each, no retry loop, no `delay`. The probe re-runs opportunistically (e.g. every minute from the service) so a chip hot-plugged after boot is picked up. Note in a comment: kernel-side Wire use is atomic against the `SYS_i2c_*` syscalls because both run in the same task context between switch points.
  - SNTP: on the `WL_CONNECTED` edge (static last-status) and hourly while connected: 48-byte request (first byte `0x1B`), `udp.beginPacket("pool.ntp.org", 123)` / `write` / `endPacket`, then non-blocking reply poll — `parsePacket()` checked per service call, 2 s deadline in `millis()`; on reply take bytes 40..43 big-endian, subtract `2208988800`, correct the clock AND `rtc_write` the epoch back to the chip (a fresh chip gets healed; chip absent → write NACKs, ignore). Failed request or DNS miss: back off 60 s, then one retry — never a loop.
  - `clock_service()`: probe-retry + the SNTP machine above, deadline-driven, returns in microseconds when nothing is due. No `k_yield`/`k_wait`, no file calls, no `delay`.

- [ ] **Step 3: `kernel.ino` wiring** — `#include "rtc.h"`; in `setup()` after `Wire.begin(); SPI.begin();` add `rtc_init();`; at each of the three console-poll sites (`read` ~156, `kbhit` ~161, `peek` ~162) add `clock_service();` beside the existing `telnetd_service();`; add the `SYS_time` case (Interfaces above) next to `SYS_delay_us`.

- [ ] **Step 4: Compile gate (no upload)** — `FQBN=rp2040:rp2040:challenger_2350_wifi6_ble5:flash=8388608_7340032,espwifitype=esp_hosted && arduino-cli compile --fqbn $FQBN --build-property "compiler.cpp.extra_flags=-I$PWD" --library third_party/ESPHost --output-dir build/kernel-challenger src/kernel` → exit 0.

- [ ] **Step 5: Invariant inspection (Review Focus 2 + 4)** — `grep -n "k_yield\|k_wait\|k_bread\|f.open\|File\|delay(\|while (WiFi" src/kernel/rtc.cpp` → empty (Wire/UDP transactions only); `git diff -- src/kernel/kernel.ino` shows the syscall switch and the poll hook as the only touched regions besides include/setup.

- [ ] **Step 6: Commit** — `git commit -am "clock: rtc kernel module - DS1307 probe, SNTP service, SYS_time"` (rtc.h/rtc.cpp `git add` first).

### Task 3: `date` tool + README

**Files:**
- Create: `src/userland/date.c`
- Modify: `README.md` (syscall table near the `reboot(mode) | 9` row; the userland tool list in the Repository layout block ~2653)

**Interfaces:**
- Consumes: `time(int*)` builtin (Task 1). The Makefile `PROGS` wildcard builds `root/bin/date.bin` with no Makefile change.
- Produces: `/bin/date` printing `YYYY-MM-DD HH:MM:SS UTC` (kernel printf supports `%0Nd`), second line `unsynced: no chip, no NTP` when the valid flag is 0.

- [ ] **Step 1: Write `date.c`** — cc-subset C: `int v = 0; int t = time(&v);` then days/secs split and civil-from-days (Howard Hinnant's algorithm, epoch 1970): `z = days + 719468; era = (z >= 0 ? z : z - 146096) / 146097; doe = z - era * 146097; yoe = (doe - doe/1460 + doe/36524 - doe/146096) / 365; y = yoe + era * 400; doy = doe - (365*yoe + yoe/4 - yoe/100); mp = (5*doy + 2)/153; d = doy - (153*mp+2)/5 + 1; m = mp < 10 ? mp+3 : mp-9; y += m <= 2;` then one `printf` of date+time from `t/86400`, `t/3600%24`, `t/60%60`, `t%60` (integer division, negatives impossible for `t >= 0`), and the unsynced line when `!v`.

- [ ] **Step 2: Build + PC run** — `make 2>&1 | tail -1` (picks up `date.c` free); `qemu-arm ./host_linux -r root /bin/date.bin` → first line equals `date -u +%Y-%m-%d` on the host (ignore the time-of-day seconds), no `unsynced` line (host returns valid=1).

- [ ] **Step 3: README** — syscall table: a `time(&valid)` | 105 row in the board block (returns seconds since 1970 UTC, stores 1 when synced / 0 while running unsynced, `valid` may be 0-pointer... it may NOT be null — state: pass an int, or 0 to ignore); Repository layout: add `date` to the userland tool list.

- [ ] **Step 4: Commit** — `git commit -am "clock: date tool + README (time syscall)"` (`git add src/userland/date.c` first).
